IBS / CBS — REFORMA TRIBUTÁRIA
Deixe em branco se o produto tem tributação normal — é o caso da maioria, e o sistema já aplica o padrão (CST 000 / classificação 000001). Preencha somente para produto com tratamento próprio: alíquota reduzida, isenção, imunidade ou monofasia. Os códigos vêm da contabilidade.
Alíquota zero não tem CST próprio. Ela se escreve como CST 200 (alíquota reduzida) com redução de 100%. É assim que entram fruta, hortaliça e ovo — por exemplo banana: CST 200, classificação 200014, redução 100.

Bem-vindo à Ponte SEFAZ

Seu emissor de notas fiscais esta pronto. Siga os passos abaixo para comecar a emitir:

1
Cadastrar empresa
Va na aba Empresas, preencha os dados e suba o certificado digital A1 (.pfx).
2
Configurar regras fiscais
Na aba Regras Fiscais, cadastre os NCMs dos produtos que a empresa vende. O contador faz isso uma vez.
3
Cadastrar produtos
Na aba Produtos, digite o nome do produto e o sistema sugere a classificacao fiscal automaticamente.
4
Emitir a primeira nota
Na aba Emissão, selecione o produto, preencha o destinatário e clique Emitir. Comece em Homologação (teste) para conferir.

Nova instância da ponte

Empacota este sistema inteiro para virar outra instalacao independente: banco proprio, certificado proprio, clientes proprios. Vai o motor fiscal, o painel, os cadastros, a revenda por chave de API e o modelo das plataformas dos clientes — a instancia nova ja nasce podendo gerar cliente.

A mesma empresa nunca pode emitir pelas duas
A numeracao das notas vive no banco, com chave (CNPJ, serie, ambiente). Dois bancos sao dois contadores que nao se enxergam: a SEFAZ recusa por duplicidade, ou pior, autoriza com buracos na sequencia que o Fisco cobra na apuracao. Divida a carteira de clientes entre as instancias — nunca a mesma empresa nas duas.

Ou publicar a ponte direto num repositorio
Crie o repositorio vazio, cole aqui e publique. Depois e so importar na Vercel (ou onde preferir), cadastrar as variaveis do .env.example e apontar o NFE_DB_URL para o seu Supabase. Nenhuma credencial vai no pacote.
Token fine-grained so alcanca repositorios da própria conta. Para publicar num repositorio de outra conta, cole aqui um token DELA — ele vale so para esta publicacao e não fica guardado: nao vai para banco, nem para log, nem para a auditoria. Vale tambem para o console, abaixo.
Gerar um token — entre na conta DONA do repositorio, escolha "Only select repositories" e marque Contents: Read and write.
Depois de publicar
  1. Crie o projeto no Supabase e copie a connection string (Settings › Database › Connection string). Escolha a do pooler, nao a "Direct connection" — a direta e so IPv6 e a Vercel nao alcanca. Senha com @ vira %40 na URL.
    Essa string e o valor de NFE_DB_URL. Ela NAO se cadastra aqui: vai no provedor da instancia nova, no passo 3 — o pacote nunca leva credencial.
  2. NFE_DB_URL="postgres://..." npx ts-node scripts/preparar-banco.ts — cria as tabelas e mostra o que criou.
  3. Importe o repositorio na Vercel, cadastre as variaveis do .env.example e publique. Cadastre antes de publicar: variável não entra em deploy que já existe.
  4. Abra o painel, cadastre o primeiro cliente e emita uma nota em homologação antes de qualquer coisa em produção.
O contrato das rotas, para construir outro front end por fora, vai no pacote em docs/API-CLIENTES.md.
